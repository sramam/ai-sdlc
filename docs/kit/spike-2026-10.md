# Platform spike, October 2026

The first spike for the preferred stack (tech-stack.md): TanStack Start on
Cloudflare Workers, Postgres through Hyperdrive, Drizzle or Prisma, Better Auth,
OpenTelemetry. It checked the items tech-stack.md, environments.md and the
Workers section of observability.md had marked to verify. It is input to a
project's ADRs, not a decision: kickoff confirms or changes each default.

**Scope.** Everything ran locally on workerd (`wrangler dev` and `vite dev`
with the Cloudflare plugin), against this repository's `pnpm db:local` PGlite.
Nothing was deployed and no Cloudflare account was used, so remote Hyperdrive,
Neon, real cold starts and OTLP delivery are not tested. Docs were read on
2026-10-15; each finding cites its page.

**Versions.** Node 24.18.0, pnpm 10.28.2, `@tanstack/react-start` 1.169.2,
`@tanstack/react-router` 1.170.44, vite 8.3.4, `@cloudflare/vite-plugin` 1.64.0,
wrangler 4.151.0, drizzle-orm 0.45.4, drizzle-kit 0.31.11, pg 8.23.1, Prisma
7.10.1, better-auth 1.7.10, zod 4.

**How.** A scratch project (`/tmp/ai-sdlc-spike-k7q2`) scaffolded with
`npm create cloudflare@latest -- app --framework=tanstack-start`, reduced to a
minimal app, then the proven result written into `docs/kit/recipes/`. The
recipes were then re-assembled from the repository into a fresh project and
run again end to end ([spike-2026-10-evidence.md](spike-2026-10-evidence.md)
§ _The recipes, re-assembled_), so what is in
`recipes/` is what was proven.

## Recommended defaults

| decision             | default                                                                                             | why                                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ORM                  | **Drizzle** with `pg` (node-postgres)                                                               | both work; Drizzle's Worker is ~5× smaller (307 vs 1,497 KiB gzip) and its first request ~2.5× faster locally. Prisma when the project needs its client extensions |
| database client      | **one per request**, from `env.HYPERDRIVE.connectionString`                                         | Cloudflare's guides; Hyperdrive is the pool                                                                                                                        |
| auth                 | **Better Auth 1.7**, email OTP, `storeOTP: "encrypted"`, built per request                          | the full flow ran under workerd                                                                                                                                    |
| tracing              | **Workers-native** `tracing.enterSpan` behind a small `Tracer` interface; OTLP export by Cloudflare | no SDK in the bundle; the port stays runtime-free; tests use an in-memory tracer                                                                                   |

Findings worth carrying into the docs:

- **`oso-cloud` 2.6.0 cannot run on Workers** (CommonJS; requires `fs`, `http`,
  `https`, `dns/promises`; reads data bindings from a file path), and
  `@authzed/authzed-node` 1.6.1 is gRPC (`@grpc/grpc-js`). Both engines'
  HTTP APIs work with `fetch`.
- **Oso local authorization meets "no dual writes" by construction**: facts are
  `SELECT`s over our tables and Oso returns SQL to run. The SQL inlines ids,
  quoted (`'x'' or …'`); it is applied with `sql.raw`, the one place a port may.
- **The Oso Dev Server refuses a policy whose Polar tests fail**
  (`400 TestsFailed`), and offers per-test environments (`POST /test_environment`).
- **SpiceDB `serve-testing` isolates by bearer token**, so a suite needs no reset;
  LookupResources over HTTP is newline-delimited JSON.
- **OpenRouter's ZDR list shows Anthropic models only through Google and Amazon
  Bedrock**, at prices that differ by endpoint; the recipe sends `max_price` at
  the highest reviewed price so the cost estimate is an upper bound.
- **Better Auth 1.7 turns its origin check off under a test runner** unless
  `advanced.disableOriginCheck: false`; with it on, a cookie-less request with no
  `Origin` is allowed and one with cookies is `MISSING_OR_NULL_ORIGIN`.
- **shadcn 4.21.5 with `-b base`** records `"style": "base-nova"`; its generated
  components use Tailwind v4 syntax (the v3 `[--x]` trap did not reproduce);
  `CommandDialog` does not wrap `<Command>`; the toaster depends on
  `next-themes`; `data-table` is a guide over TanStack Table v9, not a
  registry item; `init -d`'s help names a preset (`base-nova`) that `-p` refuses.

The per-item evidence (items 1–14, the localdb finding, the recipes re-assembled) is in [spike-2026-10-evidence.md](spike-2026-10-evidence.md).
