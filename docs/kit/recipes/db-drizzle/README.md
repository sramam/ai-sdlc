# Recipe: `db-drizzle`

Drizzle ORM on Workers through Hyperdrive, migrated by `pnpm db:local migrate`.
The recommended default (see [../../spike-2026-10.md](../../spike-2026-10.md)):
a quarter of Prisma's Worker size and about a third of its first-request time.

| file                       | is                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `src/client.ts`            | `openDb` / `withDb`: node-postgres `Client` over `{ connectionString }`, **one per request**     |
| `src/schema.ts`            | the project's tables, re-exporting Better Auth's                                                 |
| `src/auth-schema.ts`       | generated by `pnpm dlx auth@latest generate --config auth.cli.ts --output src/db/auth-schema.ts` |
| `drizzle.config.ts`        | reads `DATABASE_URL`; refuses to run without it except for `generate` (`DB-001`)                 |
| `sdlc.config.localdb.json` | the `localdb` block to merge into `sdlc.config.json`                                             |

## Rules

- **node-postgres (`pg`), not postgres.js.** Cloudflare's Drizzle guide:
  _"Pairing Drizzle ORM with the Postgres.js driver over Hyperdrive is not
  currently supported."_
- **One client per request, never at module scope.** A socket opened in one
  request cannot be used in another, and Hyperdrive is the pool.
- **Runtime-free**: the client takes `{ connectionString }`, so the binding
  passes `env.HYPERDRIVE` and a test passes a PGlite URL.
- **Migrations live in `drizzle/`**, generated (`drizzle-kit generate --name=<what>`)
  and committed; never hand-edit an applied one. They are applied by
  `pnpm db:local migrate` locally, and by the promote script against each
  environment's **direct** (non-Hyperdrive) URL.
- Drizzle records applied migrations in `drizzle.__drizzle_migrations`.
- **Better Auth checks its schema at request time.** Regenerate
  `auth-schema.ts` and a migration after any better-auth upgrade.

## The localdb block

```json
{
  "localdb": {
    "databases": [{ "name": "app", "migrate": "pnpm --filter @app/web exec drizzle-kit migrate" }]
  }
}
```

`migrate` runs from the repository root with `DATABASE_URL` set. No `env`
entry is needed: the Hyperdrive variable matters to `wrangler dev`, not to the
migration, and it needs a password localdb's URL lacks (the journeys adapter
adds one).
